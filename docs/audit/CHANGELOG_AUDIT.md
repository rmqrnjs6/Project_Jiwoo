# CHG-001: 기존 출력 경로의 자동 삭제 중단

- 기존 역할: 기능별 소스를 실행 가능한 한 디렉터리로 조립한다.
- 발견 사실: 기존 출력 경로가 존재하면 `shutil.rmtree(output)`를 호출했다. 합성 폴더의 파일이 사라지는 테스트를 먼저 실행했다.
- 변경: 직접 symlink와 기존 파일/폴더를 FileExistsError로 거부하고, 없는 디렉터리만 `mkdir(exist_ok=False)`로 확보한다. CLI 도움말과 README도 새 경로 사용법으로 맞춘다.
- 기존 / 변경 후: 같은 경로 재실행 시 전부 지우고 재생성 / 중단하고 새 경로를 요구.
- 검증: [전후 TC](TEST_MATRIX.md). 새 출력에서 실행 소스 복사가 동일한지 확인했고 기존 백엔드 77개도 유지됐다.
- 영향: 조립 CLI 사용자와 assemble() 호출자. 기존 출력 재사용 스크립트는 새 경로로 바꿔야 한다. Dockerfile의 새 `/app` 빌드는 정적으로 검토했으며 컨테이너 빌드는 미실행.
- 점수·DB·사용자 기록: 변경 없음. 테스트의 새 합성 DB 외 기존 데이터에 접근하지 않음.
- 롤백: 병합 전이면 PR을 병합하지 않으면 된다. 병합 뒤에는 이 변경 커밋을 revert하고 새 출력 경로로 재검증한다. 이전 버전의 파괴적 동작도 되돌아오므로 운영자가 검토해야 한다.
- 남은 한계: 부분 복사 실패 출력이 남을 수 있음. 운영자/동시 공격자에 대한 완전한 경로 격리 도구는 아님.
- 사용자 판단: 브랜치 수정/테스트는 추가 확인 불필요. main 병합은 별도 결정.

# CHG-002: metadata-v3 현재 의미를 테스트로 기록

실행 코드는 그대로 두고 TC 2개만 추가했다. 중립 교차 검증값이 종합점수에 7.5%p를 기여하고 peer 내용은 평가하지 않는 현재 한계를 확인한다. 진실 확률이나 검증 정확도를 입증하지 않는다. 테스트 제거로 되돌릴 수 있으며 저장 데이터·정책 버전은 바뀌지 않는다.
