# AI Judgment System(Jiwoo) — 1.0.0-rc6

> **확실한 것은 분명하게, 확실하지 않은 것은 확실하지 않다고 남긴다.**
>
> **완벽을 증명하는 시스템이 아니라, 변화할 수 있음을 증명하는 시스템.**

AI Judgment System은 세간에 떠도는 **의혹·찌라시·논란·엇갈린 주장**을 여러 근거와 함께 정리하고, 현재 시점에서 **무엇까지 명확하게 확인됐는지** 보여주는 실험적 판단 시스템입니다.

이 프로젝트의 목적은 단순히 더 많은 정보를 보여주는 것이 아닙니다.

> **더 많이 찾게 하는 것이 아니라, 이제 그만 찾아도 되는 지점을 알려주는 것.**

사용자가 여러 링크를 직접 오가며 같은 내용을 반복 확인하는 부담을 줄이고, 확인된 내용은 더 명확하게 공유하며, 정보에 붙잡히는 시간을 줄이는 것을 목표로 합니다.

---

## 프로젝트가 해결하려는 문제

온라인의 논란은 보통 정보가 없어서 어려운 것이 아닙니다.

오히려:

- 정보가 너무 많고
- 서로 다른 주장이 동시에 존재하고
- 원문과 재인용이 섞여 있고
- 무엇이 최신 정보인지 알기 어렵고
- 시간이 지나면 “그때 결국 뭐가 사실이었지?”가 다시 흐려집니다.

그래서 사용자는 같은 내용을 반복해서 검색하고 판단해야 합니다.

AI Judgment System은 이 흐름을 다음처럼 바꾸려 합니다.

```text
의혹 / 찌라시 / 논란
        ↓
관련 근거 수집
        ↓
출처와 신뢰도 확인
        ↓
현재 가장 믿을 만한 근거 강조
        ↓
현재 확인된 핵심 정리
        ↓
아직 불확실한 부분 분리
        ↓
새 근거가 생기면 다시 확인
        ↓
변화 과정 기록
```

최종적으로 지향하는 사용자 경험은:

```text
혼란 → 정리 → 확인 → 기억 → 공유 → 안심 → 자유
```

입니다.

## 가장 중요한 사용자 가치 — 정보 스트레스 감소

이 프로젝트가 줄이려는 것은 단순한 검색 시간이 아닙니다.

### 탐색 스트레스

> “어디까지 찾아봐야 하지?”

### 판단 스트레스

> “그래서 누구 말이 맞는 거지?”

### 반복 확인

> “새로운 게 또 나왔나?”

### 기억의 혼란

> “그때 결국 뭐가 사실이었지?”

시스템은 무조건적인 정답을 선언하기보다 다음 경계를 분명하게 보여주는 것을 목표로 합니다.

> **“여기까지는 확인됐고, 여기부터는 아직 확실하지 않습니다.”**

즉, 사용자에게 주려는 안심은:

> “이게 무조건 맞다.”

가 아니라:

> **“적어도 지금 확인 가능한 범위는 여기까지구나.”**

에 가깝습니다.

---

## 사용자가 기억했으면 하는 것

사용자가 근거 10개의 URL을 전부 기억할 필요는 없습니다.

이 시스템이 남기고 싶은 기억은:

> **“그때 말이 많았는데, 확인해보니 현재 명확하게 밝혀진 건 이거였지.”**

라는 하나의 정리된 기억입니다.

그래서 여러 근거를 보여주되, 그중 **지금 가장 믿을 만한 근거 1개**를 중심에 두고, 필요한 사람만 나머지 근거·세부 점수·원문까지 확인할 수 있도록 구성했습니다.

# RC6 핵심 UI

## 1. 현재 확인된 핵심

Case를 열면 가장 먼저 다음을 보여줍니다.

- 현재 확인 결과
- 지금 확인된 범위
- 아직 확인이 필요한 부분
- 현재 상태
- 지금 더 찾아봐야 하는지 판단할 수 있는 짧은 안내

표현은 내부 상태 코드보다 사람이 읽기 쉬운 문장을 우선합니다.

예:

```text
현재 범위는 정리됐어요.
공식 자료가 나오기 전까지는 조금 더 기다려야 해요.
아직 서로 다른 근거가 있어 결론이 열려 있어요.
```

---

## 2. 함께 볼 근거

기존처럼 사용자가 모든 Evidence를 직접 입력하는 방식보다, 공개된 자료에서 **5~10개의 유력한 근거 후보**를 먼저 보여주고 사용자가 직접 검수하는 흐름을 중심으로 합니다.

```text
확인할 이야기 입력
→ 근거 찾기
→ 5~10개 후보 확인
→ 필요한 근거 선택
→ 선택한 근거만 실제 판단에 사용
```

추천된 근거가 자동으로 정답이 되지는 않습니다.

사용자가 `판단에 사용`을 눌러 선택한 근거만 실제 Judgment 입력으로 사용합니다.

---

## 3. 지금 가장 믿을 만한 근거

추천 후보 가운데 현재 평가가 가장 높은 근거 **한 개만** 중심 근거로 강조합니다.

이 근거는 “절대적으로 참”이라는 뜻이 아닙니다.

> **현재 확보된 근거 가운데 가장 신뢰할 만하다고 평가된 자료**

라는 뜻입니다.

새롭고 더 강한 근거가 들어오면 대표 근거는 바뀔 수 있습니다.

이전 대표 근거를 삭제하지 않고 변경 과정은 기록합니다.

---

## 4. 신뢰도 — 숫자는 사실 확률이 아닙니다

각 근거는 다음처럼 표시됩니다.

```text
신뢰도 92% · 매우 높음
```

신뢰도는 “92% 확률로 사실”이라는 의미가 아닙니다.

현재 시스템이 확보한 정보를 기준으로 다음 요소를 종합한 **근거 평가값**입니다.

- 출처 권위성
- 원본성
- 주장과의 직접 관련성
- 자료의 최신성
- 다른 독립 근거와의 교차검토

기본 화면에서는 점수와 사람말만 간단히 보여주고, `왜 이 점수인가요?`를 열었을 때 세부 평가를 확인할 수 있습니다.

**충돌 패널티는 사용하지 않습니다.**

좋은 출처가 다른 자료와 의견이 다르다는 이유만으로 출처 자체의 신뢰도를 깎지 않습니다. 다른 근거와의 불일치는 점수 패널티가 아니라 **관계 정보**로 표시합니다.

---

## 5. 출처는 밖으로 나가기 전에 먼저 읽을 수 있습니다

근거 카드는 URL만 제공하지 않습니다.

기본 화면에서 바로:

- 출처 이름
- 게시일
- 핵심 내용
- 신뢰도
- 검증 상태
- 원문 URL

을 확인할 수 있습니다.

정말 원문 전체가 필요한 경우에만 `원문 보기`를 사용합니다.

또한 **원문에서 확인된 내용**과 **AI가 정리한 내용**을 가능한 한 구분하여, 사용자가 무엇이 원출처이고 무엇이 시스템의 설명인지 구별할 수 있도록 하는 방향을 유지합니다.

---

## 6. 출처 형식 확인과 신뢰도 평가는 다릅니다

### 출처 형식 확인

내부적으로 다음을 확인합니다.

- URL 형식이 정상인가
- 공개 웹 주소인가
- localhost/private 주소가 아닌가
- 출처 필드가 비어 있지 않은가

이 정보는 일반 사용자에게 항상 노출하지 않습니다.

문제가 있을 때만 경고합니다.

### 신뢰도 평가

> **“이 근거를 얼마나 믿을 만한가?”**

를 평가합니다.

따라서 URL이 정상이라고 해서 높은 신뢰도를 의미하지 않습니다.

```text
정부 공식 원문
출처 형식: 정상
신뢰도: 매우 높음

개인 블로그
출처 형식: 정상
신뢰도: 보통 또는 낮음
```

# 판단은 고정된 진실이 아닙니다

Judgment는 영구적인 정답이 아니라 **현재 가진 근거를 기준으로 한 판단**입니다.

```text
Judgment #1
     ↓
새 Evidence
     ↓
Reevaluation
     ↓
Judgment #2
```

재검토 후 실제 결과가 바뀌면:

```text
REVISED
```

다시 확인했지만 결과가 같으면:

```text
REAFFIRMED
```

로 구분합니다.

> **다시 생각했다는 것과 생각이 바뀌었다는 것은 서로 다른 사건입니다.**

---

# 확실하지 않을 때 억지로 결론내리지 않습니다

판단 결과:

```text
SUPPORTED
CONTRADICTED
UNCERTAIN
INSUFFICIENT_EVIDENCE
```

판단 진행 상태:

```text
RESOLVED
PENDING
UNRESOLVED
```

의미는 다음과 같습니다.

- `RESOLVED`: 현재 근거로 판단 가능
- `PENDING`: 지금은 모르지만 무엇을 기다리는지 명확함
- `UNRESOLVED`: 현재 자료로는 해결하기 어려움

즉:

> **PENDING = 아직이다**
>
> **UNRESOLVED = 현재로서는 풀리지 않는다**

---

# 판단과 행동 권한은 분리됩니다

AI가 어떤 행동이 적절하다고 판단했다고 해서 바로 실행하지 않습니다.

```text
Judgment
= 무엇이 적절한가

Permission
= 행동할 권한이 있는가

Action
= 실제로 무엇을 했는가
```

실행 전에 다음을 확인합니다.

```text
최신 Judgment인가?
↓
RESOLVED 상태인가?
↓
실행 권한이 있는가?
↓
허용된 Action인가?
↓
입력값이 유효한가?
↓
실행
```

> **행위 권한 없는 지능은 결국 조언에 머문다.**

# 함께 확인한 기록

시스템은 이전 판단을 지우지 않습니다.

Raw History에는 실제 사건을 자세히 보존하고, Timeline에서는 사람이 이해하기 쉬운 문장으로 보여줍니다.

예:

```text
첫 판단을 정리했어요.
새로운 근거가 추가됐어요.
다시 확인했지만 판단은 같아요.
새로운 자료 때문에 판단이 바뀌었어요.
같은 근거는 한 번만 반영했어요.
```

과거의 틀린 판단도 숨기지 않습니다.

> **틀린 판단을 없애는 것이 아니라, 어떻게 수정됐는지를 남깁니다.**

# 정보 공유

`공유용 요약 복사`를 통해 현재 상태를 다른 사람에게 전달할 수 있습니다.

공유 내용에는 다음이 포함됩니다.

- 확인한 주제
- 현재 확인된 핵심
- 지금까지 확인된 범위
- 아직 확인할 부분
- 현재 대표 근거
- 출처 링크
- 확인 시점
- 새 근거가 나오면 판단이 달라질 수 있다는 안내

이 기능은 현재 저장된 데이터를 사용하며 **추가 OpenAI 호출을 발생시키지 않습니다.**

목표는 상대방에게 링크 여러 개를 던지는 것이 아니라:

> **“현재 어디까지 확인됐는지”를 한 번에 공유하는 것**

입니다.

# 친근함에 대한 원칙

친근함을 단순히 귀여운 UI나 캐릭터성으로 만들지 않습니다.

이 프로젝트가 지향하는 이미지는:

> **차분하고, 친절하고, 과장하지 않지만 오래 기억되는 AI**

입니다.

그래서 기본 표현도 다음처럼 구성합니다.

```text
아직 결론을 서두르지 않았어요.
새로운 근거가 확인됐어요.
다시 확인했지만 현재 판단은 같아요.
여기부터는 아직 확인이 더 필요해요.
```

친절함은 곧 제품의 이미지가 되고, 일관된 친근함은 사용자의 기억에 남는 경험이 된다는 방향을 UI 전반에 반영하고 있습니다.

# 처음 테스트하는 방법

```text
1. 새 확인 시작
2. 확인하고 싶은 이야기 입력
3. 근거 찾기 또는 예시 보기

10. 새로 확인하기

12. 공유용 요약 복사 확인
```

API Key가 없으면 `예시 보기`를 사용해 UI 흐름을 테스트할 수 있습니다.

# OpenAI API 사용

실제 공개 웹에서 근거를 찾거나 실제 AI 판단을 실행할 때는 본인의 API Key가 필요합니다.

PowerShell:

```powershell
$env:OPENAI_API_KEY="본인의_API_Key"
```

그 뒤 서버를 재시작합니다.

> API Key를 README, GitHub, 채팅, 피드백 문서에 저장하지 마세요.

API Key를 등록하거나 서버를 켜는 것 자체로 모델 사용 비용이 발생하는 것은 아닙니다. 실제 OpenAI 요청이 발생할 때 비용이 발생할 수 있습니다.

테스트 후 현재 PowerShell 세션에서 키 제거:

```powershell
Remove-Item Env:OPENAI_API_KEY
```

# 비용 방어

AI를 호출할 수 있다고 해서 항상 호출하지 않습니다.

입력, 근거, 신뢰도, 규칙, 모델 등의 핵심 조건이 이전과 같다면 Decision Fingerprint를 비교하여 기존 Judgment를 재사용할 수 있습니다.

```text
관련 변화 없음
→ 기존 Judgment 재사용
→ 불필요한 새 AI 호출 생략
```

또한:

- 최대 Evidence 개수
- 총 입력 길이
- 출력 토큰
- Reasoning 강도

등을 제한해 과도한 요청을 방지합니다.
